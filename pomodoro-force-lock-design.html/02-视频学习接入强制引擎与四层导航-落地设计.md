## 1. 现状与差距

对照 v2.0 §2.6，当前 视频学习模式距设计有三个明确的缺口：

| 设计要求 | 现状 | 差距 |
|---|---|---|
| 点击视频自动全屏并**锁定**全屏（Esc/F11/缩小均无效） | 仅以 `fullscreen: autoFullscreen` 创建窗口，可随意 Esc 退出 | 缺全屏锁定守卫 |
| 四层导航判定（域名→路径→历史→内容）+ 严格/宽松档 | `guard.ts` 只有 L1 域名 + L2 路径 | 缺 L3 历史锁定、L4 内容相关性；`strictness` 未消费 |
| 视频学习模式受强制引擎守护（L1/L2 分级） | `biliWindow.ts` 明确"核心版，不接强制引擎" | 缺强制会话联动 |

工程的既有能力可以复用：强制引擎 `beginEnforcement / endEnforcement`（锁定分级、快捷键守卫、窗口拉回、守护进程、紧急退出、统计落库）、`shortcutGuard`（已全局拦截 F11/Ctrl+W/T/R/F5）、`LEVEL_CAPS`、`settings.lockLevel / bili.strictness / bili.autoFullscreen`。本方案的核心工作是把这些能力"接到 视频学习播放窗口上"，并补全 L3/L4 判定。

## 2. 总体架构

新增两个能力模块，并让既有模块互通：**fullscreenLock**（全屏锁定守卫）与 **guard 四层判定**；把 `enforcement` 从"只锁主窗口"泛化为"可锁任意目标窗口"，视频学习播放窗口成为受控目标。编排责任放在 `navigation` 模块——它持有 enforcement 句柄，在打开视频时启动强制会话，在关闭时结束。

```
渲染层                                      主进程
─────────────────────────────              ─────────────────────────────────────────────
BiliModePage（搜索结果）                    navigation/index.ts（编排）──▶ enforcement
OverlayApp（AI/记事本）                      │                              enterBiliSession
window.api.bili.*                           biliWindow.ts（播放窗口）
                                            guard.ts（L1–L4 判定）           fullscreenLock.ts
                                            shared/bili.ts 类型               shortcutGuard / windowGuard / level
```

实线为强制控制流，虚线为只读/事件流。

## 3. 强制引擎接入

把 `enforcement/index.ts` 的会话生命周期泛化为可指定目标窗口。改动最小化：`begin/endEnforcement` 增加可选 `target` 参数，缺省仍回落到主窗口（不动专注模式既有行为）。

### 3.1 begin/endEnforcement 泛化

```ts
// src/main/enforcement/index.ts
function beginEnforcement(
  mode: string,
  plannedMs: number,
  target?: BrowserWindow   // 新增：视频学习会话传播放窗口
): void {
  const level = getSettings().lockLevel
  emergency.assertExitSafety(level)
  const win = target ?? getWindow()
  if (!win) return
  const sessionId = recordSessionStart({ mode, level, startedAt: Date.now(), durationPlanned: plannedMs }) ?? 0

  applyLevelWindow(win)                        // 锁定作用于目标窗口
  if (LEVEL_CAPS[level].globalShortcuts) registerShortcutGuard()
  windowGuard.start(win, level, currentPolicy) // 失焦拉回目标窗口
  if (LEVEL_CAPS[level].killTaskmgr) startTaskmgrKill()
  if (LEVEL_CAPS[level].guardian) spawnGuardian()

  active = { level, mode, startedAt: Date.now(), sessionId }
  setSettings({ enforced: { active: true, level, mode, startedAt: active.startedAt, plannedMs, sessionId } })
}
```

`endEnforcement(reason, target?)` 同理：`releaseLevelWindow(win)` 用 target 或主窗口，其余释放逻辑复用。

### 3.2 暴露 视频学习专属句柄

```ts
// 返回句柄（registerEnforcementModule 现有返回对象扩展）
export interface EnforcementHandle {
  restoreAfterRestart: () => void
  /** 打开 学习视频时启动强制会话（正向计时 + 会话上限） */
  enterBiliSession: (videoWin: BrowserWindow, opts: { plannedMs: number; topic: string }) => void
  /** 关闭 学习视频时结束强制会话并落库 */
  exitBiliSession: (reason: 'manual' | 'completed' | 'emergency') => void
}

function enterBiliSession(videoWin: BrowserWindow, opts): void {
  // 正向计时，会话上限 = min(用户选择, sessionMaxHours)
  const cap = Math.min(
    opts.plannedMs,
    getSettings().sessionMaxHours * 3600_000
  )
  beginEnforcement('bili', cap, videoWin)
  timer.start({ mode: 'countup', durationMs: cap })
}
```

同时把 `onTimerComplete` 里硬编码的 `'focus'` 改为按当前会话 `active.mode` 落库，使 视频学习会话也能正确写入 `study_stats` 与模式对比。

### 3.3 编排接线（navigation/index.ts）

```ts
// registerNavigationModule 签名增加 enforcement 句柄
import type { EnforcementHandle } from '../enforcement'

export function registerNavigationModule(
  getWindow: () => BrowserWindow | null,
  enforcement: EnforcementHandle
): void {
  registerVideoEvents({
    getMainWindow: getWindow,
    // 打开视频 → 启动强制会话 + 全屏锁定（autoFullscreen 由 payload 决定）
    onOpen: (video, payload) => {
      enforcement.enterBiliSession(video, { plannedMs: payload.plannedMs ?? 0, topic: payload.topic ?? '' })
      attachFullscreenLock(video, {
        autoFullscreen: payload.autoFullscreen,
        active: () => !video.isDestroyed()
      })
    },
    // 视频关闭 → 结束强制会话
    onClose: () => enforcement.exitBiliSession('manual')
  })
  // ...既有搜索 / navCheck / notes IPC...
}
```

主进程装配处把 enforcement 句柄传入导航模块：

```ts
// src/main/index.ts
const enforcement = registerEnforcementModule(getMainWindow)
registerNavigationModule(getMainWindow, enforcement)
```

## 4. 全屏锁定

新增 `navigation/fullscreenLock.ts`。核心思路：**Esc 不全局拦截**（需留给渲染层"连按 5 次 Esc"紧急退出），而是用 `leave-full-screen / exit-full-screen / resize` 三个事件的兜底拉回来"重新进全屏"，形成"怎么退都退不出"的效果。F11 / Ctrl+W/T/R/F5 已由 `shortcutGuard` 全局消费。

```ts
// src/main/navigation/fullscreenLock.ts
import type { BrowserWindow } from 'electron'

export interface FullscreenLockOpts {
  autoFullscreen: boolean
  /** 是否仍处于强制会话（结束时置 false 解除锁定） */
  active: () => boolean
}

export function attachFullscreenLock(win: BrowserWindow, opts: FullscreenLockOpts): void {
  if (opts.autoFullscreen) win.setFullScreen(true)

  const assertFullscreen = (): void => {
    if (opts.active() && !win.isFullScreen()) {
      win.setFullScreen(true)   // 兜底拉回：Esc / 缩小 / F11 之后立即恢复
    }
  }
  win.on('leave-full-screen', assertFullscreen)
  win.on('exit-full-screen', assertFullscreen)
  win.on('resize', assertFullscreen)

  // 可选加固：在渲染层消费 Escape 键，避免触发一次"退出→拉回"的闪烁
  win.webContents.on('before-input-event', (_e, input) => {
    if (opts.active() && input.key === 'Escape') _e.preventDefault()
  })
}
```

> **Electron 限制**：没有 `setFullScreenable(false)` 这类原子 API，退全屏会被浏览器默认行为触发，因此采用"事件兜底拉回"，会在极端情况下产生一帧闪烁。这是可行且工程上最常见的做法；若追求零闪烁，可在 `before-input-event` 预先消费 Escape（已在上方作为可选加固）。

## 5. 四层导航判定

把 `guard.ts` 从"纯 URL 谓词"升级为"URL 判断 + 行为守卫 + 内容判断"三件套，并接收 `BiliGuardContext`（主题、档位、放行 BV 集合）。

### 5.1 判定职责拆分

| 层级 | 判定器 | 触发点 | 拦截处理 |
|---|---|---|---|
| L1 域名 | `isAllowedBiliUrl`（既有） | `will-navigate / did-navigate` | 拦截提示页 |
| L2 路径 | `isAllowedBiliUrl`（既有 + 严格档 BV 白名单） | 同上 | 拦截提示页 |
| L3 历史 | `HISTORY_TRAP` 注入脚本 + popstate 兜底 | 页面加载后注入；`did-navigate-in-page` | 拉回当前搜索语境 |
| L4 内容 | `isRelevantContent(title, tags, ctx)` | 视频页加载后提取标题/标签 | 标准档警告 / 严格档拦截 |

### 5.2 守卫上下文（跨模块传递）

```ts
// src/shared/bili.ts 新增
export interface BiliGuardContext {
  /** 学习主题（来自搜索关键词） */
  topic: string
  /** 相关度档位：strict / standard / loose */
  strictness: BiliStrictness
  /** 严格档可放行的 BV 集合（当前搜索结果列表） */
  allowedBvs: string[]
}
```

当前会话上下文由 `biliWindow` 维护（已有 `currentTopic`），扩展为 `currentCtx`，并在每次判定时读取 `settings.bili.strictness`——从此档位设置真正生效。

### 5.3 L3 历史锁定

```ts
// 注入脚本：覆写 history 计数 + 拦截 popstate（后退/侧键）
const HISTORY_TRAP = `
  (() => {
    const push = history.pushState, rep = history.replaceState
    history.pushState = function (...a) { window.__navSteps = (window.__navSteps || 0) + 1; return push.apply(this, a) }
    history.replaceState = function (...a) { window.__navSteps = (window.__navSteps || 0) + 1; return rep.apply(this, a) }
    window.addEventListener('popstate', () => {
      // 后退想离开当前语境 → 立刻 push 回当前 URL，禁止离开
      if (location.href) history.pushState(null, '', location.href)
    })
  })()
`

// 在 attachNavigationGuard 内，页面加载后注入；并保留 will-navigate 判定
target.on('did-finish-load', () => {
  target.executeJavaScript(HISTORY_TRAP).catch(() => /* 页面限制时降级：仅靠事件兜底 */)
})
```

> **降级策略**：若 视频学习页面 CSP 阻止注入，L3 退化为"仅靠 `will-navigate` 域名/路径判定"，功能不中断（§3.7 回归清单要求 L4 脚本容错降级，L3 同理）。

### 5.4 L4 内容相关性

视频页加载后提取标题与标签，与主题做关键词匹配。匹配规则：主题切分为 token（中文细粒度、英文按词），任一 token（或其同义词）命中标题/标签即判相关；标注"标记为相关"可把某 BV 加入放行集合。

```ts
const CONTENT_EXTRACTOR = `
  (() => {
    const title = document.title || document.querySelector('h1')?.textContent || ''
    const tags = Array.from(document.querySelectorAll('a[href*="tag"]'))
      .map(a => a.textContent).join(' ')
    return { title, tags }
  })()
`

// isRelevantContent：主题 token 命中标题/标签
export function isRelevantContent(
  title: string,
  tags: string,
  ctx: BiliGuardContext
): boolean {
  const tokens = tokenize(ctx.topic)          // 中文：按字/词；英文：按词
  const hay = title + ' ' + tags
  return tokens.some((t) => hay.includes(t) || SYNONYMS[t]?.some((s) => hay.includes(s)))
}

// 严格档：仅当 BV 在放行集合内才放行
export function isBvAllowed(bvid: string, ctx: BiliGuardContext): boolean {
  return ctx.strictness !== 'strict' || ctx.allowedBvs.includes(bvid)
}
```

## 7. 关键代码：guard.ts 重写要点

把原 `attachNavigationGuard` 改为携带上下文，并接入 L3/L4。核心是在既有 `will-navigate / setWindowOpenHandler / did-navigate / did-navigate-in-page` 基础上，增加内容判定回调。

```ts
export function attachNavigationGuard(
  target: WebContents,
  ctx: BiliGuardContext,
  callbacks?: GuardCallbacks
): void {
  const judge = (url: string): boolean => {
    if (!/^https?:/i.test(url)) return true
    const verdict = isAllowedBiliUrl(url, ctx)   // L1 域名 + L2 路径 + 严格档 BV 白名单
    if (!verdict.allowed) {
      callbacks?.onBlocked?.(verdict, target)
      return false
    }
    return true
  }

  // ...既有的 will-navigate / setWindowOpenHandler / did-navigate / did-navigate-in-page 复用 judge...

  // L4：视频页加载后提取标题/标签做相关性判定
  target.on('did-finish-load', async () => {
    target.executeJavaScript(HISTORY_TRAP).catch(() => /* 降级 */)
    if (ctx.strictness === 'loose') return   // 宽松档不做 L4
    try {
      const { title, tags } = await target.executeJavaScript(CONTENT_EXTRACTOR)
      if (!isRelevantContent(title, tags, ctx)) {
        handleIrrelevant(ctx, target)   // 标准档：警告悬浮层；严格档：拦截页
      }
    } catch { /* 提取失败 → 容错降级，不误拦 */ }
  })
}
```

拦截页复用 `buildBlockPageHtml`，为**无关内容**新增提示文案与"标记为相关"按钮（点击调 `bili:mark-relevant` 后回到搜索页）。标准档的警告通过主窗口渲染层以悬浮条呈现，不阻断播放。

## 8. 严格 / 标准 / 宽松档位

| 档位 | L1 域名 | L2 路径 | L3 历史 | L4 内容 | BV 白名单 |
|---|---|---|---|---|---|
| strict 严格 | 拦截 | 拦截 | 锁定 | **拦截**（无关即阻断） | 仅放行搜索结果内 BV |
| standard 标准（默认） | 拦截 | 拦截 | 锁定 | 警告不阻断 | 否 |
| loose 宽松 | 拦截 | 拦截 | 锁定 | 不启用 | 否 |

档位由 `settings.bili.strictness` 决定，每次打开视频时读取并构造 `BiliGuardContext`。设置页修改档位后即时生效（下次开视频生效）。

## 9. 测试与回归

- **单元测试（Vitest）**：`isAllowedBiliUrl` 各层用例（L1 非白名单域名、L2 直播/番剧/影视/动态、严格档 BV 白名单）；`isRelevantContent` 关键词/同义词命中与未命中；`tokenize` 中英文切分。
- **集成冒烟**：真实打开 学习视频，验证自动全屏；Esc/F11/缩小后自动拉回；点击后台推荐链接被拦截；关闭窗口后强制会话结束、统计落库。
- **回归清单（§3.7）**：视频学习页面结构变更后 L3/L4 注入脚本容错降级，不影响播放；CSP 禁止注入时功能不中断；杀毒软件对 `taskkill` 的误报在 L2 已存在，此方案不新增。
