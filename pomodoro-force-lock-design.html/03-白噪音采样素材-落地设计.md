## 1. 现状与差距

白噪音引擎（渲染层 Web Audio）已经就绪：`seamlessLoop.ts` 实现双节点交叉淡入淡出无缝循环，`synth.ts` 提供白/粉/棕噪合成层，`presets.ts` 定义了合成层 + 采样层共 11 个预设。缺口在采样层这一环：

| 环节 | 现状 | 缺口 |
|------|------|------|
| 音频文件 | `resources/audio/` 只有 README.md | 8 个 `.ogg/.wav` 素材文件缺失 |
| 传输到渲染层 | `audio:get-assets` 只返回路径与 exists | 渲染层无法 fetch 文件系统路径，缺可访问 URL |
| 解码 | `decodeSample` 返回 null（占位） | 采样轨永远被跳过 |

因此即使混音引擎和数据契约都齐备，预设选择"雨声/咖啡厅/森林…"时采样轨仍不发声，用户只能听到合成噪声。本方案解决"素材从哪来 + 怎么送到引擎解码"两个问题。

## 2. 总体方案

采用"**程序化合成优先 + CC0 录音可替换**"的双轨策略，保证离线、零依赖、可复现：

- **程序化合成**：用纯 Node 脚本（无第三方依赖）按每种素材的声学配方生成 44.1kHz/16-bit 循环音频，输出 WAV；若本机有 `ffmpeg` 则额外转码为体积更小的 OGG（符合 §2.8"OGG 优先"）。
- **CC0 可替换**：任何真实 CC0 录音只要按同名覆盖进 `resources/audio/` 即可无缝替换（规格一致即可），脚本生成的是"开箱即用"的兜底。

传输上，主进程注册一个自定义协议 `tomato-audio://` 流式读取 `resources/audio/` 下的文件，渲染层 `decodeSample` 经 `fetch(url) → decodeAudioData` 解码并内存缓存。这样生产环境 asar 外置素材也能被渲染层读取。

```

           │ 打包 asarUnpack 外置
```

## 4. 生成管线

新增 `scripts/generate-samples.mjs`，纯 Node 运行，无第三方依赖。核心是三个可复用原语：噪声生成器、双二阶滤波器、WAV 写出器，外加每种素材的合成函数。

```js
// scripts/generate-samples.mjs
import { writeFileSync, mkdirSync, existsSync } from 'node:fs'
import { spawnSync } from 'node:child_process'
import { join, dirname } from 'node:path'
import { fileURLToPath } from 'node:url'

const SR = 44100, DUR = 45          // 44.1kHz，45s 循环素材
const N = SR * DUR
const OUT = join(dirname(fileURLToPath(import.meta.url)), '..', 'resources', 'audio')

/* ---- 噪声原语 ---- */
function white(n = N) { return Float32Array.from({ length: n }, () => Math.random() * 2 - 1) }
function pink(n = N) {          // Paul Kellet 三极近似
  const out = new Float32Array(n)
  let b0 = 0, b1 = 0, b2 = 0
  for (let i = 0; i < n; i++) {
    const w = Math.random() * 2 - 1
    b0 = 0.99765 * b0 + w * 0.0990460
    b1 = 0.96300 * b1 + w * 0.2965164
    b2 = 0.57000 * b2 + w * 1.0526913
    out[i] = (b0 + b1 + b2 + w * 0.1848) * 0.25
  }
  return out
}
function brown(n = N) {
  const out = new Float32Array(n)
  let last = 0
  for (let i = 0; i < n; i++) {
    const w = Math.random() * 2 - 1
    last = (last + 0.02 * w) / 1.02
    out[i] = last * 3.5
  }
  return out
}

/* ---- 双二阶带通/低通（RBJ 系数） ---- */
function biquad(src, { type, fc, q = 0.707 }) {
  // 计算系数后逐样本滤波；type ∈ 'lowpass' | 'bandpass' | 'highpass'
  const w0 = 2 * Math.PI * fc / SR
  const alpha = Math.sin(w0) / (2 * q)
  const cw = Math.cos(w0)
  let b0, b1, b2, a0, a1, a2
  if (type === 'lowpass') {
    b0 = (1 - cw) / 2; b1 = 1 - cw; b2 = b0
    a0 = 1 + alpha; a1 = -2 * cw; a2 = 1 - alpha
  } else {  // bandpass（peak 增益 = 1）
    b0 = alpha; b1 = 0; b2 = -alpha
    a0 = 1 + alpha; a1 = -2 * cw; a2 = 1 - alpha
  }
  const out = new Float32Array(src.length)
  let x1 = 0, x2 = 0, y1 = 0, y2 = 0
  for (let i = 0; i < src.length; i++) {
    const x = src[i]
    const y = (b0 * x + b1 * x1 + b2 * x2 - a1 * y1 - a2 * y2) / a0
    x2 = x1; x1 = x; y2 = y1; y1 = y
    out[i] = y
  }
  return out
}

/* ---- 写出 WAV（16-bit PCM） ---- */
function writeWav(name, samples) {
  const num = samples.length, dataSize = num * 2
  const buf = new Buffer(44 + dataSize)
  buf.write('RIFF', 0); buf.writeUInt32LE(36 + dataSize, 4); buf.write('WAVE', 8)
  buf.write('fmt ', 12); buf.writeUInt32LE(16, 16); buf.writeUInt16LE(1, 20); buf.writeUInt16LE(1, 22)
  buf.writeUInt32LE(SR, 24); buf.writeUInt32LE(SR * 2, 28); buf.writeUInt16LE(2, 32); buf.writeUInt16LE(16, 34)
  buf.write('data', 36); buf.writeUInt32LE(dataSize, 40)
  let peak = 0
  for (let i = 0; i < num; i++) {
    const s = Math.max(-1, Math.min(1, samples[i]))
    peak = Math.max(peak, Math.abs(s))
    buf.writeInt16LE(Math.round(s * 32767 * 0.707), 44 + i * 2)  // 预衰减到 -3dB
  }
  writeFileSync(join(OUT, name + '.wav'), buf)
  return peak * 0.707
}

/* ---- 循环安全：在 45s 周期上放置瞬态，避开首尾 1.5s 接缝 ---- */
function placeEvents(out, count, make, seed = 1) {
  let rnd = seed
  const rand = () => (rnd = (rnd * 16807) % 2147483647) / 2147483647
  for (let i = 0; i < count; i++) {
    const t = 1.6 + rand() * (DUR - 3.2)   // 避开首尾接缝
    make(out, Math.floor(t * SR))
  }
}
```

> **转码**：生成完 WAV 后探测 `ffmpeg`，存在则逐文件转 OGG（`ffmpeg -i in.wav -c:a libvorbis -q 4 out.ogg`）并删除 WAV；不存在则保留 WAV。无论哪种，文件名与 `shared/audio.ts` 的 `SAMPLE_ASSET_SPECS.file` 对应（见 §6 探测逻辑，兼容 `.ogg` / `.wav` 两种存在形态）。

## 5. 8 种素材合成方案

每种素材 = 若干"轨"（噪声经滤波 + 调制 + 瞬态）叠加，最后归一化。下面给核心配方与关键参数，均保证周期性（LFO 频率能整除 45s）与接缝安全。

| 素材 | 配方 | 关键参数 |
|------|------|----------|
| rain | 白噪→带通(1–4kHz)做雨幕 + 棕噪低通(120Hz)做隆隆底 + 短促雨滴瞬态 | 带通 fc≈2kHz；雨滴 = 8ms 白噪脉冲带通 3–6kHz，每 0.4–1.1s 一个 |
| cafe | 白噪→带通(250–3kHz)做人声 babble + 低频嗡 + 稀疏杯碟 clink | babble 用 LFO（0.5Hz）慢速调制音量；clink = 2ms FM 正弦 2→4kHz |
| forest | 宽频柔噪(叶响) + 合成鸟鸣 | 叶响 = 带通 2–6kHz + 随机 AM；鸟鸣 = FM 上扫 1.5→3.5kHz，随机间隔 |
| library | 极低底噪 + 最淡翻页瞬态 | 低通棕噪 200Hz；翻页 = 60ms 带通 1–2kHz 噪声包络，每 6–14s 一次 |
| waves | 带通白噪 + 慢速幅度 LFO（涌浪） | 带通 400Hz q0.5；LFO 0.1Hz（45s 恰 4.5 周期，循环无缝）深度 0.85 |
| fire | 低频噼啪噪声 + 高频爆裂瞬态 | 带通 100–800Hz 基底；爆裂 = 5ms 白噪脉冲 + 指数衰减，随机 |
| fan | 低通棕/粉噪 + 120Hz 电机 AM | 低通 600Hz；AM 用 0.2Hz LFO 微调增益（±8%） |
| birds | 合成 FM 鸣唱叠加 + 极淡环境底 | 鸣唱 = 2–4 个音节的 1.5–4kHz 上扫，随机时段；音量最小（0.5） |

```js
// 例：rain 合成（其余类似，按配方表组织）
const RECIPES = {
  rain() {
    const curtains = biquad(white(), { type: 'bandpass', fc: 2000, q: 0.6 })
    const rumble = biquad(brown(), { type: 'lowpass', fc: 120 })
    const out = new Float32Array(N)
    mix(out, curtains, 0.9); mix(out, rumble, 0.5)
    placeEvents(out, 90, (o, i) => placeRaindrop(o, i), 7)
    return out
  },
  // cafe / forest / library / waves / fire / fan / birds ...
}

for (const [name, fn] of Object.entries(RECIPES)) {
  writeWav(name, fn())
  maybeToOgg(name)
}
```

> **接缝安全原则**：所有瞬态事件落在 `1.6s ~ DUR-1.6s` 区间（接管缝避开）；所有 LFO/AM 频率取 `k / DUR`（周期整除循环长）。即便个别残余，引擎的 1.5s 交叉淡入淡出也会掩盖。

## 6. 主进程：本地协议

渲染层不能 fetch 文件系统路径，需主进程注册自定义协议 `tomato-audio://`。协议须在 app ready 前声明特权，故在 `main/index.ts` 顶部与 `audio/index.ts` 各加一段。

```ts
// src/main/index.ts · app.whenReady 之前（模块顶层）
import { protocol } from 'electron'
protocol.registerSchemesAsPrivileged([
  { scheme: 'tomato-audio', privileges: { standard: true, secure: true, stream: true } }
])
```

```ts
// src/main/audio/index.ts · 注册协议处理器 + 为 AssetInfo 提供可访问 URL
import { protocol, net, globalShortcut, ipcMain, app } from 'electron'
import { pathToFileURL } from 'node:url'

function audioDir(): string {
  return app.isPackaged
    ? join(process.resourcesPath, 'audio')
    : join(app.getAppPath(), 'resources', 'audio')
}

// 探测 .ogg 优先、.wav 兜底（兼顾无 ffmpeg 环境）
function resolveAssetInfos(): AssetInfo[] {
  const dir = audioDir()
  return SAMPLE_ASSET_SPECS.map((spec) => {
    const ogg = join(dir, spec.file)
    const wav = join(dir, spec.file.replace(/\.ogg$/, '.wav'))
    const file = existsSync(ogg) ? ogg : existsSync(wav) ? wav : ogg
    return {
      ...spec,
      path: file,
      exists: existsSync(file),
      url: `tomato-audio://` + basename(file)   // 新增：渲染层可 fetch 的 URL
    }
  })
}

// 协议处理器：流式返回 resources/audio/ 下的文件
protocol.handle('tomato-audio', (request) => {
  const file = new URL(request.url).hostname   // tomato-audio://rain.ogg → 'rain.ogg'
  const full = join(audioDir(), file)
  if (!existsSync(full)) return new Response(new Uint8Array(), { status: 404 })
  return net.fetch(pathToFileURL(full).toString())
})
```

> **路径安全**：URL 的 host 只取文件名并 `basename` 清洗，join 前拒绝任何含路径分隔符的输入，防目录穿越。

## 7. 渲染层：decodeSample

替换 `engine.ts` 的占位 `decodeSample`：经 `getAssets` 拿到带 `url` 的 AssetInfo，`fetch → decodeAudioData`，成功即按 key 缓存，避免重复解码。原有"素材不可用则跳过"的分支继续生效。

```ts
// src/renderer/src/audio/engine.ts
private bufferCache = new Map<string, AudioBuffer>()

private async decodeSample(ctx: AudioContext, key: SampleKind): Promise<AudioBuffer | null> {
  if (this.bufferCache.has(key)) return this.bufferCache.get(key)!
  try {
    const info = (await window.api.audio.getAssets()).find((a) => a.key === key)
    if (!info || !info.exists || !info.url) return null
    const res = await fetch(info.url)
    if (!res.ok) return null
    const buf = await ctx.decodeAudioData(await res.arrayBuffer())
    this.bufferCache.set(key, buf)
    return buf
  } catch {
    return null
  }
}
```

同时把 `shared/audio.ts` 的 `AssetInfo` 增加可选 `url?: string` 字段，preload 类型随之更新。

## 8. 打包配置

`electron-builder.yml` 已配置 `files: resources/**` 与 `asarUnpack: resources/**`，素材会随包分发并外置到 `process.resourcesPath/audio/`，与 `audioDir()` 的生产路径一致，无需改动。仅需确认新增的 `.wav/.ogg` 未被 `files` 排除（当前规则不排除音频，放行）。

> **体积提示**：8 个 45s 素材——OGG（q4）约 250–500KB/个，总量约 3MB；WAV 约 4MB/个，总量约 32MB。优先用 OGG 以控制安装包体积（§2.8 单文件 ≤5MB 达标）。

## 10. 验收标准

- 运行 `npm run samples:generate` 后，`resources/audio/` 出现 8 个素材文件（ffmpeg 存在则 .ogg，否则 .wav）。
- 应用中选择"雨声/咖啡厅/森林/图书馆/海浪/篝火/风扇/鸟鸣"任一预设，采样轨发声；合成层与采样层可混音（如咖啡厅 = cafe + 棕噪底）。
- 循环播放 60s 无爆音、无明显接缝（双节点交叉淡入淡出生效）。
- 生产打包后启动应用，采样仍可播放（asar 外置素材经 `tomato-audio://` 正常读取）。
- 素材缺失时采样轨自动跳过、提示，不崩溃（既有降级逻辑）。
- 按 URL 构造路径无法穿越目录（basename 清洗生效）。
