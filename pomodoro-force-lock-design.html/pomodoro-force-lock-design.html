01项目概述与设计目标

本软件是一款面向 PC 的强制专注型番茄钟，核心差异点在于"强制"二字：不仅提醒你专注，更通过系统级手段阻断分心路径。软件内置三种学习模式，分别针对"视频学习""语言学习""纯专注"三类场景，并支持白噪音叠加。

B 站学习模式

输入学习主题 → 打开 B 站搜索结果 → 锁定在该主题的搜索页与子页面内，无法返回首页或跳转其他内容。

英语学习模式

进入内置 AI 对话页，以母语者水平的 AI 讲解语法、单词、语句，可联网检索，提供全面讲解。

专注模式

与一般番茄钟一致，进入软件计时系统（不熄屏），支持正序/逆序计时、学习时长分析与番茄自动提示。

白噪音

可在英语学习与专注模式下叠加白噪音，提升沉浸感。

设计目标

  • 强制有效：三种模式均具备系统级强制能力，常规绕过手段（刷新、重启、切窗口、任务管理器）均被阻断。
  • 场景专注：每种模式只开放与学习目标相关的功能，其余路径全部关闭。
  • 易用可配：模式切换、学习主题输入、白名单设置均在一分钟内完成。
  • 跨平台：优先 Windows，兼容 macOS；核心逻辑与 UI 层跨平台复用。
核心设计理念

软件采用"沙箱化学习"思路：把一次学习会话封装成一个受控环境，环境内只保留达成学习目标所需的入口，环境边界由系统级强制机制守护。这与市面常见的"提醒式"番茄钟形成本质区别，更接近 Cold Turkey 的 Frozen Turkey 锁机模式与 kiosk 单应用模式的结合体。

02总体架构与技术选型

技术选型对比

方案 跨平台 系统级强制能力 浏览器导航管控 开发效率 体积 结论
Electron + 原生模块 强 通过 Node 原生模块 / PowerShell / AppleScript 调用系统 API 内置 Chromium，可完全控制内置浏览器；外部浏览器需配套扩展 高（JS 生态） 大（~150MB+） 推荐：生态成熟，内置浏览器可控性最强
Tauri + Rust 强 Rust 调用系统 API 更底层 内置 WebView 受系统限制，控制力弱于 Chromium 中（Rust 门槛） 小（~10MB） 备选：轻量但内置浏览器控制力弱
Python (PySide6) 中 可调用系统 API 需外部浏览器 + 扩展 中 中 适合原型验证（如 Hardcore-Pomodoro 即此方案）
原生 (C#/Swift) 弱 最强 需外部浏览器 + 扩展 低 小 单平台深度定制时可选
推荐方案

采用 Electron + 原生辅助模块。理由：B 站学习模式需要"完全可控的内置浏览器"，Electron 的 Chromium 内核可以精确拦截导航、注入脚本、锁定页面，这是其他方案难以做到的；系统级锁屏、进程管控、熄屏（可选）通过 Node 侧调用系统 API 实现，跨平台封装成本可控。

模块划分

关键设计决策

  • 内置浏览器优先，外部浏览器兜底：B 站模式优先使用 Electron 内置浏览器（完全可控）；若用户坚持使用系统浏览器，则通过配套 Chrome/Edge 扩展实现导航管控（参考 Strict URL Whitelist 的 declarativeNetRequest 思路）。
  • 强制引擎与 UI 解耦：强制控制逻辑放在主进程独立模块，即使渲染层崩溃，强制状态依然生效。
  • 会话级状态机：所有模式共用一套番茄钟状态机（FOCUS / BREAK / LOCKED），模式只是"锁定策略"的差异。
  • 管理员权限：Windows 下需要管理员权限（UAC 提权）才能执行锁屏、改 hosts、杀进程等操作，安装时申请。

03模式一 · B 站学习模式

B 站学习模式

需求拆解

用户输入学习主题后，软件打开 B 站搜索结果页，并建立一个学习沙箱：用户只能停留在"与该主题相关的搜索结果页及其子页面"内，不能返回 B 站首页、不能跳转到无关内容、不能打开其他页面。点击进入视频后自动切换为全屏观看，且只能在全屏模式下观看，无法缩小屏幕。会话期间软件提供内嵌 AI 学习助手（可联网搜索学习中遇到的问题）与记事本（遇到问题及时记录），且刷新无法重置学习状态。

核心矛盾

B 站是"内容海洋"，搜索页与视频页内嵌大量无关推荐（首页推荐、侧栏推荐、评论区外链、视频结尾推荐）。"只允许学习相关内容"的管控粒度需要精确到导航来源与 URL 特征双重判定，而非简单的域名白名单。同时，"全屏强制观看"与"AI 助手、记事本"并存，要求界面在沉浸与辅助之间取得平衡。

工作流程

① 输入学习主题→ ② 生成搜索 URL→ ③ 打开内置浏览器→ ④ 点击视频自动全屏→ ⑤ 全屏锁定 + 导航管控→ ⑥ AI 助手 / 记事本辅助→ ⑦ 到点强制休息

搜索 URL 构造

B 站网页搜索使用 https://search.bilibili.com/all?keyword=关键词 格式，关键词通过 URL 编码传入[1]。软件将用户输入拼接为搜索 URL 后在内置浏览器中打开。

URL 构造示例const keyword = encodeURIComponent(userInput.trim());
const searchUrl = `https://search.bilibili.com/all?keyword=${keyword}`;
// 例：输入 "Python 教程" → https://search.bilibili.com/all?keyword=Python%20%E6%95%99%E7%A8%8B

导航管控规则（核心设计）

采用三层判定，从宽到严，命中即放行，全部未命中则拦截：

层级 判定依据 放行条件 拦截处理
L1 域名层 目标 URL 域名 仅允许 bilibili.com 及其子域名 非 B 站域名一律拦截
L2 路径层 URL 路径特征 允许：搜索页 /all、视频页 /video/BV*、用户空间 /space/*、专栏 /read/*、合集页 拦截首页 /、直播 /live、番剧 /bangumi、影视 /movie、动态 /opus 等无关板块
L3 内容层 页面内容相关性（注入脚本检测） 视频标题/标签包含学习主题关键词或其近义词 不相关内容页面显示"与学习主题无关"提示并拦截
关键实现细节：L3 内容层判定

仅靠 URL 无法判断视频内容是否相关（例如搜索"Python"后点进一个"Python 搞笑合集"）。因此在内置浏览器中注入内容检测脚本，读取页面 <title> 与视频标签，用关键词匹配（支持同义词扩展）判断相关性。L3 判定失败时给出提示页，用户可"标记为相关"（需输入验证码式确认，防止误操作），或返回搜索页重新选择。

全屏强制观看（核心新特性）

点击搜索结果中的视频后，软件自动将内置浏览器切换为全屏模式，并锁定全屏状态，用户无法缩小窗口或退出全屏。这是本模式"沉浸学习"的关键保障。

交互动作 处理方案 实现层级
点击视频进入播放 检测到 /video/BV* 页面加载完成，自动调用 webContents.executeJavaScript 触发 B 站播放器全屏（或 Electron setFullScreen(true)） 主进程 + 注入脚本
Esc / F11 退出全屏 拦截全屏退出事件，退出后立即重新进入全屏；快捷键在渲染层被屏蔽 渲染层 + 主进程
窗口缩小 / 拖动 全屏窗口禁用窗口缩放与拖动；resize 事件被监听，非全屏尺寸立即恢复 主进程 BrowserWindow
点击"退出全屏"按钮 B 站播放器按钮被注入脚本劫持，点击无效或弹提示"学习模式下无法退出全屏" 注入脚本
播放器内其他功能 倍速、进度条、弹幕开关、画质选择等正常使用，仅锁定全屏状态 注入脚本
全屏与辅助功能的平衡

全屏观看时，AI 助手与记事本以悬浮侧栏形式叠加在视频上方（可折叠），通过鼠标移到屏幕边缘呼出，不打断视频播放。这样既保持全屏沉浸，又能在遇到问题时随时提问或记录，符合"其他功能正常使用"的需求。

内嵌 AI 学习助手

B 站学习模式下内置一个 AI 对话助手，用于解答学习中遇到的问题，并具备联网搜索能力。它与英语模式的 AI 网关共用底层，但 Prompt 定位不同：这里是"学习答疑助手"，聚焦于解释视频中遇到的难点。

  • 唤起方式：全屏悬浮侧栏常驻入口，或快捷键（如 Ctrl+Shift+A）呼出。
  • 提问方式：文本输入为主；支持"截图提问"（截取当前视频画面发送给多模态模型，可选）。
  • 联网检索：遇到视频中未讲透的概念，助手主动联网搜索补充资料，并附来源。
  • 上下文感知：助手可读取当前视频标题与学习主题，回答时结合上下文，而非泛泛而谈。
  • 记录联动：AI 回答可一键存入记事本，形成"问题—解答—笔记"闭环。

记事本

提供轻量级记事本，用于学习过程中随时记录问题、重点与灵感。设计要点：

  • 快速记录：全屏悬浮侧栏内嵌编辑器，快捷键（如 Ctrl+Shift+N）一键唤起，输入即保存。
  • 自动保存：内容实时写入本地（防抖 500ms），断电/崩溃不丢失。
  • 时间戳：每条笔记自动附带时间与当前视频标题，便于回看定位。
  • 标签与检索：支持简单标签与关键词搜索，方便会话结束后整理。
  • 导出：会话结束可导出为 Markdown 学习笔记。

状态机

实用建议

  • 主题关键词管理：允许用户保存常用学习主题，一键进入；支持"主题+子主题"（如"Python"+"爬虫"）以提升搜索相关性。
  • 相关度阈值可调：提供"严格/标准/宽松"三档内容相关度，严格档要求标题强匹配，宽松档仅做域名+路径管控。
  • 学习记录：自动记录本次会话浏览的视频列表与时长，会话结束后生成学习小结，增强正反馈。
  • 全屏策略可配：提供"自动全屏"开关，关闭后点击视频以普通窗口播放（适合需要对照代码/文档的用户），但导航管控仍生效。
  • AI 助手成本控制：B 站模式 AI 助手与英语模式共用 API 额度，可设置单次会话提问上限，避免成本失控。
  • 外部浏览器兜底：若用户必须用系统浏览器，提供配套扩展，扩展内实现相同的三层判定逻辑（参考 Strict URL Whitelist 的 declarativeNetRequest 方案[2]）。

04模式二 · 英语学习模式

英语学习模式可叠加白噪音

需求拆解

进入该模式后，软件自动打开内置的 AI 对话页面。AI 以英语母语者水平对用户提出的英语语法、单词、语句进行解释，并具备联网检索能力以提供全面讲解。该模式同样处于强制专注状态，无法切换到其他应用。

页面结构

对话区

流式展示 AI 回复，支持 Markdown 渲染（语法高亮、例句卡片、音标标注）。

输入区

支持文本输入、语音输入（可选）、快捷指令（查词/造句/纠错/翻译）。

学习面板

生词本、语法要点卡片、本次会话学习摘要。

白噪音控件

雨声、咖啡厅、白噪声等，音量独立调节。

AI 网关设计

AI 能力通过网关层统一封装，支持接入 OpenAI 兼容 API（GPT / Claude / 通义 / DeepSeek 等），便于替换与成本控制。

  • 对话模型：负责语法讲解、单词释义、语句分析、纠错与对话。
  • 联网检索：模型侧启用联网搜索（如 OpenAI web search / 通义联网），或网关层先调用搜索 API 获取资料再注入上下文，确保讲解基于真实信息。
  • 流式输出：SSE 流式返回，提升交互体验。
  • 上下文管理：会话内保留对话历史（滑动窗口），支持"追问"语义连贯。

System Prompt 设计（母语者水平）

这是本模式的核心。设计原则：角色设定 + 水平分级 + 讲解规范 + 纠错机制 + 输出格式五要素。完整模板见附录，核心要点如下：

Prompt 核心设计原则

好的英语教学 Prompt 需要三个要素：用户水平（A1–C2）、明确角色与目标（"act as an English tutor"）、要求带理由的纠错[3]。母语者水平意味着：讲解使用地道英语、能解释"为什么这么说"的语感差异、能区分正式/口语/俚语语境。

  • 角色：资深英语母语教师（Native English Teacher），精通语法、词汇、语用与文化背景。
  • 语言策略：默认全英文讲解；用户明确要求中文时，先给英文解释再给中文对照，避免全程中文（参考 LingoMate 的"三连尝试后仍失败才转中文"策略[4]）。
  • 讲解结构：先直接回答 → 给出地道例句 → 解释语法/用法 → 指出常见错误 → 提供练习。
  • 纠错机制：用户写句子时，先肯定优点，再逐条纠错并说明原因，最后给出改写版本。
  • 联网检索：涉及文化背景、词源、最新用法时主动检索，并标注信息来源。

交互场景示例

用户输入 AI 响应结构
查词："serendipity" 什么意思？ 音标 + 词性 + 英文释义 + 中文对照 + 2-3 个地道例句 + 使用场景说明 + 词源小知识（联网）
语法："I suggest him to go" 对吗？ 指出错误 → 正确用法 "I suggest (that) he go" → 解释 suggest 后接虚拟语气 → 对比常见错误 → 练习
写作："帮我润色这段话" 先肯定 → 逐句润色并标注改动原因 → 给出改写版 → 总结可复用的表达
对话："和我聊聊天气" 以母语者口吻自然对话 → 对话中纠正用户错误 → 会话结束给出错误总结

防绕过与强制设计

  • 该模式运行在软件内置页面中，不涉及外部浏览器，天然无法跳转其他网页。
  • Alt+Tab / 任务管理器 / 重启等绕过手段的处理与 B 站模式一致（见第 3 章防绕过表）。
  • AI 对话页在专注期间同样受番茄钟约束，到点进入强制休息。

实用建议

  • API Key 管理：支持用户自填 API Key（BYOK），或内置服务端代理（需后端）。为控制成本，建议默认使用性价比高的模型，高级讲解可切换更强模型。
  • 离线兜底：断网时提供本地词库查询（如内置词典），避免完全不可用。
  • 学习数据本地化：生词本、对话记录保存在本地，尊重隐私。
  • 语音输入/朗读：可选接入 TTS 朗读例句、STT 语音输入，强化听说练习。

05模式三 · 专注模式

专注模式可叠加白噪音

需求拆解

专注模式与一般番茄钟一致，不熄屏，进入软件自带的计时系统界面。支持正序计时（从 0 开始累加）与逆序计时（从设定时长倒计时到 0）两种方式。软件会分析学习时长并生成统计，同时提供番茄学习模式（25 分钟专注 + 5 分钟休息循环），到点自动提示。该模式同样处于强制专注状态，无法切换到其他应用。

设计定位

专注模式是三种模式中"最接近普通番茄钟"的一种：不强锁屏幕、不熄屏，重点是计时 + 统计 + 自动提示，适合需要看屏幕写代码、读文档、做练习的场景。强制能力主要体现在"无法切换到其他分心应用"这一层。

计时方式

计时方式 说明 适用场景
正序计时 从 0 开始累加，记录本次专注实际用时，无固定时长上限 自由学习、写代码、阅读，不设限的深度工作
逆序计时 从设定时长（如 25/45/60 分钟）倒计时到 0，到点自动提示 番茄工作法、限时任务、考试模拟

番茄学习模式（自动提示）

内置标准番茄工作法循环：25 分钟专注 + 5 分钟休息，每 4 个番茄后进入 15-30 分钟长休息。到点通过声音提示 + 桌面通知提醒，无需用户盯表。

  • 专注结束：播放提示音 + 弹出"休息一下"通知，自动进入休息倒计时。
  • 休息结束：再次提示"开始下一个番茄"，自动进入下一轮专注。
  • 可自定义：专注/休息时长、每轮番茄数均可配置（如 45/10、90/15）。
  • 自动衔接：番茄循环默认自动进行，也可手动暂停/跳过休息。

学习时长分析

软件自动记录每次专注会话的时长与分布，生成可视化统计，帮助用户了解自己的学习投入。

  • 会话统计：本次专注时长、完成番茄数、中断次数。
  • 日/周/月趋势：每日专注总时长柱状图、每周对比，直观看到投入变化。
  • 时段热力图：统计一天中哪个时段专注效率最高（参考番茄ToDo 的统计设计[10]）。
  • 模式对比：区分三种模式的专注时长，了解学习时间分配。

强制控制设计

  • 计时界面置顶：计时窗口可置顶显示，但不强制全屏，用户可正常使用其他学习软件（如 IDE、文档），仅拦截分心应用。
  • 分心应用拦截：会话期间检测并强制关闭黑名单应用（浏览器、游戏、社交软件），白名单应用（IDE、文档、终端）正常使用。参考 Focuser 的杀进程思路[5]。
  • 前台窗口检测：周期性检测前台窗口，若为黑名单应用则警告并强制拉回。
  • 防重启绕过：会话状态持久化，重启后自动恢复计时。
  • 紧急退出机制：为防止误锁导致无法使用电脑（如 Focuser 用户误设 72 小时导致"废了"的教训[5]），必须提供安全出口：输入预设密码，或"连续按 N 次空格"式验证解锁。
安全设计：紧急退出

参考 BreakTimer 的"按 99 下空格解锁"机制[6]，专注模式提供两级出口：① 会话内可设置"提前结束密码"（默认关闭）；② 无论何种情况，长按电源键或重启后进入系统登录界面前，软件提供"输入预设恢复码"解锁，避免用户被永久锁死。

状态机

实用建议

  • 默认逆序：首次使用默认逆序 25 分钟，符合番茄钟直觉；正序作为进阶选项。
  • 白名单预置：预置常见学习软件白名单（VS Code、IDE、Office、PDF 阅读器），减少误杀。
  • 提示音分级：专注结束用柔和提示音，休息结束用稍强提示音，避免惊吓。
  • 统计反馈：会话结束后展示本次专注时长与累计统计，形成正反馈。

06白噪音功能设计

白噪音

需求拆解

白噪音可在英语学习模式与专注模式中叠加，提升沉浸感。设计要点：音源、播放引擎、控制交互、与强制模式的兼容。

音源方案对比

方案 音质 体积/成本 离线 结论
程序合成（Web Audio API 生成白噪/粉噪/棕噪） 中（真实感一般） 零体积零成本 支持 基础白噪/粉噪推荐用此方案
预置音频文件（雨声/咖啡厅/海浪等） 高（真实采样） 每首 1-5MB 支持 自然音效推荐，打包 6-10 首精选
流媒体（在线白噪音 API） 高 需订阅/带宽 不支持 不推荐（违背离线专注理念）

推荐音源组合

  • 合成层：白噪、粉噪、棕噪（Web Audio API 实时生成，零成本）。
  • 采样层：雨声、雷雨、咖啡厅、海浪、篝火、风扇、森林鸟鸣等 6-10 首精选自然音（预置音频）。
  • 混合层：支持"白噪 + 雨声"等叠加混合，音量独立调节。

播放引擎设计

  • 使用 AudioContext 管理音频，支持循环无缝播放（音频文件做淡入淡出交叉处理，避免接缝爆音）。
  • 音量平滑过渡（渐变 500ms），避免突然切换的突兀感。
  • 与番茄钟联动：专注开始自动播放（可配置），休息时自动暂停或降低音量。
  • 专注模式下音频持续播放，作为沉浸氛围的一部分。

控制交互

  • 英语学习模式：侧边栏常驻白噪音控件（开关、音源选择、音量）。
  • 专注模式：进入前在设置页选择音源，进入后通过"盲操作热键"（如 Ctrl+Shift+↑/↓ 调音量）控制，避免破坏全屏沉浸。

浏览器导航管控（内置浏览器）

Electron 内置浏览器通过 webContents 的 will-navigate 与 webRequest.onBeforeRequest 事件实现三层判定：

Electron 导航拦截核心代码const { session } = require('electron');

// 拦截所有导航请求
session.defaultSession.webRequest.onBeforeRequest(
  { urls: ['*://*/*'] },
  (details, callback) => {
    const decision = navigationGuard.evaluate(details.url);
    if (decision.allowed) {
      callback({ cancel: false });
    } else {
      // 重定向到拦截提示页
      callback({ redirectURL: `app://blocked?reason=${encodeURIComponent(decision.reason)}` });
    }
  }
);

// 拦截页面内跳转
webContents.on('will-navigate', (event, url) => {
  if (!navigationGuard.evaluate(url).allowed) {
    event.preventDefault();
    webContents.loadURL(blockedPageUrl(url));
  }
});

强制引擎架构

防绕过边界说明（诚实声明）

强制能力的边界

任何软件级强制都存在极限：进入 Windows 安全模式、使用 PE 启动盘、重装系统等系统级操作仍可绕过（Cold Turkey 用户实测证实安全模式可绕过屏蔽[7]）。本设计的目标是"显著提高绕过成本"，让普通分心行为（刷新、切窗口、开新标签）无法实现，而非对抗系统管理员级别的操作。产品文档中应如实说明这一边界，避免用户误以为"绝对不可破解"。

安全边界

所有系统级操作（锁屏、杀进程、hosts 改写）只允许在主进程执行，渲染进程通过 contextBridge 暴露的受限 API 调用，避免渲染层被注入恶意脚本后直接控制系统。IPC 通道做白名单校验。

Node.js 20 LTS（Electron 28 要求 Node 20+）
包管理器 pnpm（速度快、磁盘占用小）
代码规范 ESLint + Prettier + Husky（提交前检查）
测试 Vitest（单元测试）+ Playwright（UI 测试）
版本管理 Git + GitHub/Gitee 私有仓库
CI/CD GitHub Actions（构建、测试、打包、发布）

开发流程

① 需求拆分→ ② 分支开发→ ③ 单元测试→ ④ 代码审查→ ⑤ 合并主干→ ⑥ CI 构建→ ⑦ 内测发布→ ⑧ 正式发布
  • 分支策略：Git Flow 简化版（main + develop + feature/*）。
  • 测试重点：番茄钟状态机（纯逻辑，Vitest 全覆盖）、导航判定规则（三层判定单元测试）、强制引擎（集成测试，需真实系统环境）。
  • 强制功能测试：锁屏/杀进程等系统级功能无法在 CI 中完整测试，需在真实 Windows/macOS 机器上做冒烟测试，建议维护一台测试机。

打包与签名

平台 安装包格式 签名 说明
Windows NSIS 安装包（.exe）+ 便携版（.zip） 代码签名证书（EV 或 OV，如 DigiCert / Sectigo） 签名避免 SmartScreen 拦截；建议同时提供免安装版便于试用
macOS DMG + 公证（notarization） Apple Developer ID 证书 + notary 未公证会被 Gatekeeper 拦截

自动更新

  • 使用 electron-updater 实现增量自动更新，更新源可托管在 GitHub Releases 或自建服务器。
  • 更新包需与安装包同样签名，否则更新会被系统拦截。
  • 强制功能相关更新（如 B 站页面结构变化导致的内容检测脚本失效）应支持热更新规则：导航判定规则与内容检测脚本可远程下发，无需整包更新。

分发渠道

渠道 适用阶段 说明
GitHub / Gitee Releases 内测 + 正式 免费、支持自动更新源
官网下载页 正式 需自建简单静态页 + 下载统计
应用商店（Microsoft Store / Mac App Store） 正式（可选） 商店对"杀进程/改 hosts"等权限审查严格，可能被拒，建议以官网分发为主
网盘（蓝奏云等） 内测 国内用户下载快，但无法自动更新
商店分发风险提示

本软件的核心能力（杀进程、改 hosts、屏蔽任务管理器）属于敏感系统操作，Microsoft Store 与 Mac App Store 的沙箱与权限审查很可能拒绝此类应用。建议以官网 + GitHub Releases为主要分发渠道，商店渠道仅作补充或放弃。

发布检查清单

  • 代码签名完成且验证通过（Windows SmartScreen / macOS Gatekeeper）。
  • 强制功能在干净系统（无开发环境）上冒烟测试通过。
  • 紧急恢复码机制验证：误锁后能正常解锁。
  • 杀毒软件误报检查：提交 VirusTotal 扫描，必要时申请白名单。
  • 自动更新链路验证：旧版本能正常升级到新版本。
  • B 站内容检测脚本在当前 B 站页面结构下验证通过。

界面布局设计原则

  • 深色主题：全应用深色，降低长时间学习的视觉疲劳；番茄红橙为强调色，蓝为辅助色。
  • 沉浸优先：B 站全屏、专注模式均以"减少干扰"为第一原则，辅助功能（AI/记事本）默认折叠。
  • 快捷键体系：常用操作全部支持快捷键（呼出 AI、记事本、暂停/结束计时），减少鼠标操作。
  • 响应式：主界面支持窗口缩放，B 站全屏与专注模式固定全屏。
